## 一、产品定位

**Everony**（旧代号 Furry Everpony；曾用候选名 Everony，用户 2026-11-16 20:57 定名 Everony）：一台服务器、纯网页、Bot 广场 + 多 Bot 群聊的私密角色扮演聊天站。
用户用**邮箱 + 密码**注册登录，拥有一个**自选的 8–11 位数字号码**（对外展示，Bot 用它识别并记忆这个人）。

## 三、技术方案要点（实现层）

- **后端**：复用现有 Fastify + SQLite；拆掉联邦/邀请码/中继相关接口与 UI 入口。
- **前端**：复用现有 React UI；首页改为 Bot 广场；去掉加好友流程。
- **Bot 接入（用户 2026-11-16 20:36 纠正）**：接入的是**对方自己的框架**（AstrBot / Koishi / NoneBot2），消息转发到他们的框架，人设、记忆、插件都在他们那边；我们这边只做：接入登记、定时探活、消息转发、限流、卡片标注（提供者/门槛/“消息会发送给该提供者”）、公开或不公开。
  - 协议首选 **OpenAI 兼容** `POST /v1/chat/completions`（含 SSE）：Koishi / NoneBot2 有现成插件，AstrBot 用我们提供的插件；另可留原生 webhook 协议作为备选。
  - 表：`bot_endpoints(id, owner_user_id, name, avatar, tags, base_url, api_key, protocol, is_public, status, last_seen_at)`；探活每 60 秒，5 秒超时。
- **记忆**：`bot_memory(user_no, bot_id, summary, updated_at)`，按轮数压缩摘要；换设备可恢复。
- **免加好友直聊**：已改好后端 `canOpenDm`（公开 Bot 可直接开聊），待编译测试。

## 四、固定地址（实测结论 + 方案 B 落地）

**实测（2026-11-16 20:40）**
- 本机内网 `192.168.18.69`，出口 `223.74.1.250`（移动）。
- `tracert` 路径：192.168.18.1 → 192.168.0.1 → 192.168.2.1 → 192.168.1.1 → **172.21.0.1（运营商内网）** → 223.74.1.250 → 运营商多层 NAT，无独立公网 IPv4。
- 无 IPv6（`curl -6` = NO_IPV6）。
- 外部 4 个节点（西班牙/以色列/伊朗/瑞典）对 18080 全部超时 → 公网入站不可达，**DDNS 直连不可行**。

**方案 B（用户已选）= 免费内网穿透**
- 首选：樱花 FRP 免费隧道（官网实测：隧道限速 10 Mibps、2 条隧道、每月 5 GiB 流量、每日签到加流量、免备案），地址为固定的 `*.natfrp.com` 子域名（同一隧道 ID 地址不变）。
- 备选：Tailscale Funnel（固定 `*.ts.net`，无月流量限制，国内速度看线路）。
- 限制：地址前缀由服务商给，**做不到 fluffylia 开头**；要自己的名字 = 自有域名（约 70 元/年）+ 支持自定义域名的穿透（多数需实名/备案）或 Cloudflare Tunnel。
- 可用性：机器 7×24 开机（用户已确认可以关屏后台常开）+ frpc 开机自启 + BIOS 来电自启；机器断电/断网/重启期间页面打不开。
- 解耦：域名只出现在配置里，将来升级到自有域名只改一处，用户数据不丢，旧地址可保留跳转。

### 4.1 免费/低价域名路线盘点（2026-11-16 20:55 追加）

前提：本机无公网入口，任何域名最终都要配一条「通道」（穿透）。免费域名能否用，取决于通道是否接受该域名的 Host/CNAME。

| 路线 | 名字长什么样 | 费用 | 能否配合免费通道 | 风险/代价 |
|---|---|---|---|---|
| EU.org | `everony.eu.org` | 0 | **能**：可设 NS → 交给 Cloudflare → Cloudflare Tunnel，自己名字 + 固定地址 + 自动 HTTPS | 人工审核，排队极慢（数周至一年+），站点老旧 |
| ClouDNS 免费子域名 | `everony.cloudns.net` | 0 | 部分可行（需试 NS 委派，免费版常不给） | 免费版查询限制 |
| dpdns.org / us.kg（DigitalPlat） | `everony.dpdns.org` | 0 | 能改 A/CNAME；能否被穿透服务接受要看服务商 | 所有权在提供方，可能回收 |
| js.org / is-a.dev | `everony.js.org` | 0 | 需 GitHub PR 审核 | 面向开源项目，不适合聊天站 |
| 便宜 TLD | `everony.xyz` / `.top` | 首年约 1 美元 / 几元 | 能（自有域名，可上 Cloudflare） | 续费涨价 |
| 自有域名（.com 等） | `everony.com` | 约 70 元/年 | 能，最稳 | 花钱 |
| 穿透服务商域名 | `xxx.natfrp.com` / `xxx.ts.net` | 0 | 天生就是通道 | 不是自己的名字 |
| 免费 PaaS 域名 | `xxx.vercel.app` / `*.pages.dev` | 0 | 后端会休眠/限流 | 不适合长期 |

**推荐排序**：① EU.org（0 元 + 自己名字，先排队）→ 下来前先用穿透服务商域名跑；② dpdns.org（立即可用）；③ 自有域名 70 元/年（最稳）。
