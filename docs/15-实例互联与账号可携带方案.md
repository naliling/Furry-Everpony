# 15 · 实例互联与账号可携带方案（v0.10.10 起）

## 为什么必须这么设计

Furry Everpony 的每个实例都是一个独立服务端（自己的数据库、自己的账号体系）。
这带来两个必然结果：

1. **号码只在实例内唯一**。你在自己的实例里注册 100001，别人在他的实例里也注册 100001，两者毫无关系。
   所以"输入号码就能找到人"在纯单实例架构下永远不成立——不是 bug，是架构决定的。
2. **跨实例必须互相能连上**。两台机器要交换消息，至少一方能被另一方访问到（局域网 IP、公网 IP、
   端口映射或内网穿透）。这是网络物理约束，任何软件都绕不过去。

## 不做中心服务器，也不托管

中心服务器（云上跑一个公共的账号目录 + 消息中转）确实能免掉"填地址"，但代价是：
你成为数据控制者，要承担内容责任、数据安全责任和合规义务——这正是用户明确拒绝的。

所以本方案**零中心依赖**：

- 局域网内：UDP 广播自动发现同网段的其它实例，不用填任何地址。
- 局域网外：把"实例地址"（`IP:端口` 或 DDNS 域名）发给对方，或扫二维码。
- 消息：直接实例 → 实例投递，不经过任何第三方。

## 核心概念

- **实例身份**：每个实例首次启动生成 `instance_id`（随机 16 字节 hex），存在 `instance_meta` 表。
- **远端联系人**：对方实例上的人，在本库里存成 `accounts.type = 'remote'` 的账号行，
  带 `remote_addr`（对方实例地址）、`remote_instance`、`remote_secret`（双方共享密钥）。
  这样私聊会话、消息表、未读数、置顶、免打扰等全部逻辑**零改动复用**。
- **共享密钥**：好友关系建立时，接受方生成随机密钥，回执给对方；之后双向投递都带
  `x-fe-instance` + `x-fe-secret` 头，接收方校验不通过直接 403。

## 协议（实例间）

### 1. 加好友

```
A 实例（发起方）                       B 实例（被加方）
POST {B}/api/federation/handshake
{ from_instance, from_addr, from_number,
  from_nickname, from_avatar, to_number, message }
                                    → 找到 to_number 的账号
                                    → 建/取 type=remote 的 A 号账号（remote_addr=from_addr）
                                    → 写一条 friend_requests（from=远端账号, to=目标）
                                    ← { ok:true, pending:true }

用户在 B 端点"同意"
POST {A}/api/federation/accept
{ instance_id, secret, from_number(B 的号),
  to_number(A 的号), nickname, avatar }
                                    → A 端建 type=remote 的 B 号账号（含密钥）
                                    → 双向 friendships
```

### 2. 发消息

```
POST {B}/api/federation/deliver
headers: x-fe-instance, x-fe-secret
{ from_number, to_number,
  message: { kind, body, meta, reply_body?, created_at } }
                                    → 校验密钥
                                    → 落到本地 dm 会话，sender = 远端账号
                                    → WebSocket 推给在线端
```

A 端发消息时：先在本地落库（界面立刻可见），再进 `federation_outbox` 队列；
后台每 4 秒扫一次到期行投递，失败按指数退避重试（5s→10s→…→最长 5 分钟，最多 60 次）。
对方实例离线时消息不会丢，等它上线自动补投。

### 3. 局域网发现

UDP 7799 广播 `{"fe":1,"instanceId":"…","version":"…","port":7788}`，每 5 秒一次。
收到广播的实例记录对端（20 秒内有心跳算在线），并去拉一次
`GET {peer}/api/federation/directory`（返回本实例的用户号列表：号码、昵称、头像）。
这样同一 Wi-Fi 下，手机端打开"添加好友"就能直接看到电脑上的账号，点一下就能加。

## 本实例对外的接口（前端用）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/federation/info` | `{instanceId, version, port, boundToLan, lanUrls, publicAddr, myAddresses}` |
| PATCH | `/api/federation/settings` | `{publicAddr}` 设置公网地址（可空），返回归一化后的值 |
| GET | `/api/federation/nearby` | `{instances:[{instanceId, addr, port, version, lastSeen, numbers:[{number,nickname,avatar,type}]}]}` |
| POST | `/api/federation/lookup` | `{addr, number}` → `{account, isFriend, hasPending}`；addr 留空 = 本实例 |
| POST | `/api/federation/request` | `{addr, number, message?}` → `{ok:true, pending:true}` |

`/api/friends` 的每项新增 `remote: boolean` 与 `addr: string`（远端实例地址，本机好友为空串）。
`/api/users/:number` 返回的 account 同样带 `remote` / `addr`。

## 已知限制（v0.10.10）

- 跨实例只支持**单聊**。群聊仍是单实例内的（跨实例群需要成员同步与权限协商，下一版再做）。
- 撤回/表情/正在输入不跨实例同步（消息本体跨）。
- 双方都在 NAT 后面且没有公网地址时连不上，需要端口映射或用内网穿透（后续可加打洞）。
- 远端联系人没有真实的在线状态，`online` 恒为 false。
