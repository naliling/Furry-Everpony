# 中继服务器（自建与使用）

> 一句话：两台设备不在同一个网络、家里又没有公网地址时，加一台**你自己**的中继当邮局，好友申请和消息就能排着队送到对方手上。

## 为什么需要它

Furry Everpony 是自托管的：每个实例在自己的电脑/手机上跑服务，实例之间直连。
直连有个硬前提——**对方此刻能被连上**。家用宽带通常没有公网 IPv4，光猫/路由器默认拦入站，IPv6 又未必有。
结果就是：同一个 Wi-Fi 下加好友没问题，一旦换网络就报「对方实例没连上」。

中继把「必须现在可达」换成「排队等人来取」：

- 每个实例**主动出站**连中继（注册 + 心跳 + 每 8 秒拉一次），不需要任何入站端口映射，也不需要公网地址；
- 发不出去的投递（好友申请 / 好友回执 / 私聊消息）先丢给中继排队；
- 对方上线后自己来拉，拉完回执确认，中继立刻删掉。

**中继不存账号、不存聊天记录主体、不参与加密**，队列里的东西最多放 7 天。数据仍然在各自的实例里，中继只是邮局。
不配中继 = 完全不参与，行为和以前一模一样（纯直连）。

## 跑起来

```bash
# 在一台有公网地址的机器上（VPS、家里的软路由、云主机都行）
node server/relay.js            # 默认监听 0.0.0.0:7800

# 换端口 / 换监听地址 / 换数据库文件
FE_RELAY_PORT=9000 FE_RELAY_HOST=127.0.0.1 FE_RELAY_DB=/var/lib/fe/relay.db node server/relay.js
```

数据库默认落在 `~/.furry-everpony/relay.db`（SQLite，WAL 模式），只有两张表：`relay_instances`（登记过的实例）与 `relay_queue`（待取事件）。

自检：

```bash
curl http://<中继地址>:7800/api/health
# {"ok":true,"role":"relay","version":"…","instances":2,"queued":0}
```

`instances` 是登记过的实例数，`queued` 是当前排队事件数（正常应该长期是 0 或个位数）。

## 让实例用上它

电脑端：**设置 → 实例互联 → 中继服务器**，填 `https://relay.example.com:7800`（不写协议就按 http:// 处理），点保存。
状态行会显示「已连上 <地址>」；把输入框清空再保存就是关掉，回到纯直连。

手机端：同一个开关（设置 → 实例互联）。安卓本地服务的实现是 `android/server-src/fe/local/Relay.java`，协议与电脑端完全一致。

两台设备**都要配**，否则只有配了的那一端能发、另一端收不到。

## 部署建议

- 放在有 HTTPS 的域名后面（Nginx/Caddy 反代 7800），客户端填 `https://…`；中继本身只讲 HTTP，TLS 交给反代。
- 中继数据库会随实例数量增长，`relay_queue` 里的事件按 7 天过期清理，`relay_instances` 每行只有几十字节，长期跑不用担心。
- 中继宕机不影响直连：客户端每 8 秒拉一次会报错并记 `lastError`，直连链路照常工作。
- 一台中继可以服务任意多个实例；实例按 `instanceId` + 密钥隔离，别人拿不到你的队列。

## 接口（想自己写客户端时看这里）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/health` | 公开健康检查（实例数、队列长度） |
| POST | `/api/relay/register` | `{instanceId, secret, addr, version}` 登记实例（同 ID 换密钥会被 403） |
| POST | `/api/relay/heartbeat` | `{instanceId, secret}` 心跳 |
| POST | `/api/relay/send` | `{from, secret, to, kind, payload}`，`kind` 只能是 `handshake` / `accept` / `deliver` |
| GET | `/api/relay/pull` | `?instanceId&secret&since&limit` → `{events:[{id,from,kind,payload,at}], next, more}` |
| POST | `/api/relay/ack` | `{instanceId, secret, ids}` 取走确认，确认后删除 |
| GET | `/api/relay/status` | 不带参数返回公开聚合；带 `instanceId` 必须同时给 `secret` |

客户端实现见 `server/relay-client.js`（电脑端）与 `android/server-src/fe/local/Relay.java`（手机端），两边协议逐字一致。

## 联调与测试

```bash
# 电脑端：一台中继 + 两个实例，验证排队、拉取、回执、消息投递
node server/scripts/test-relay.mjs

# 手机端：真实中继 + 两个安卓本地服务，验证「只有实例 ID 也能加好友」
node android/test/relay-test.mjs
```

两个脚本都会临时起中继（随机端口、临时库），跑完自动清理，不会污染正式数据。
