# 自写服务端方案（取代 06 的 Matrix 路线）

> 版本：v2026.11.13.0.2.0
> 状态：**当前生效的架构方案**。`06-基于Matrix的改造方案.md` 降级为参考，不再作为实施依据。

## 一、为什么放弃 Matrix 服务端

用户 m01420 定案「要做成软件」，并在选项里选定：**每个用户下载的软件里自带服务器，各自是一个独立实例，实例之间互相加好友**。

这个约束和 Matrix 直接冲突，理由是可查证的：

1. **tuwunel 只有 Linux 构建。** v2.0.0 的 release 资产全部是 `linux-gnu`（deb / rpm / zst / docker / oci / nix），没有任何 Windows 或 macOS 产物。
2. **它根本编不出 Windows 版。** `Cargo.toml` 里同时依赖 `libc` 和 `nix`——`nix` 是 Unix 专用 crate，只在 Linux/BSD 上可用；数据库还是自编译的 `rust-rocksdb` 分支。这不是"没打包"，是"代码层面就跑不了"。
3. **没有替代品。** Synapse 官方只支持 Linux（Windows 属"不支持"状态）；Dendrite 已于 2024-11 归档停更；Conduit / tuwunel 同为 Rust + RocksDB，问题一样。

所以「软件自带服务器」这条要求，Matrix 生态在 Windows 上无解。剩下只有两条路：给用户装 WSL2（要管理员、要重启、下 G 级虚拟盘，普通人到这就走了），或者自己写服务端。

**结论：服务端自己写。** Matrix 那一套（06 文档）保留作参考，其中的判断——数字号码可行、好友申请制、Bot 归属与审批、全免费——全部继承。

## 二、产品形态

一个 Windows 桌面软件（后续 macOS / Linux 同源构建）。

```
Furry Everpony.exe
├── Electron 主进程
│   ├── Fastify 服务端（HTTP + WebSocket）   ← 就是"实例"
│   ├── SQLite 数据库（单文件）
│   └── 窗口 / 托盘 / 开机自启管理
└── 渲染进程（React）
    └── 聊天界面（号码、好友、Bot）
```

- 双击安装 → 双击打开 → 直接就是自己的实例，不需要另装任何东西。
- 实例默认只监听 `127.0.0.1:7788`（单机模式）。开启「允许别人加我」后才监听 `0.0.0.0`。
- 数据在 `%APPDATA%\FurryEverpony\data\everpony.db`，卸载不删数据（可选）。
- 没有中心服务器，没有账号注册服务，没有联网激活。

## 三、为什么是 Electron 而不是 Tauri

| | Electron | Tauri |
|---|---|---|
| 服务端跑在哪 | 主进程原生 Node，Fastify 直接跑 | 需要把 Node 服务打成 sidecar 二进制（SEA / pkg） |
| 安装包 | 约 110–130 MB | 约 5–10 MB |
| 开发速度 | 快，无额外工具链 | 需要 Rust 工具链，打包链路长 |

选 Electron：**服务端就是 Node，天然跑在主进程里**，不用把服务端二次打包成二进制，也不用为了打包引入 Rust 工具链。安装包大一点，换开发速度和稳定性，值得。以后真嫌大再换 Tauri，服务端代码不用改。

## 四、协议（自写，跨实例用）

- 实例身份：首次启动生成 Ed25519 密钥对，公钥的 SHA-256 前 16 字节十六进制即**实例指纹**。
- 用户全限定地址 `fqid = 指纹.号码`，例如 `a3f9c2d1e8b74f60.3632823490`。界面只显示号码。
- 好友关系存对端指纹 + 公钥，防止跨实例冒充（这是 QQ 串号事故的直接教训）。
- 跨实例消息带签名：`sender_fqid + conversation_id + body + ts + nonce`，接收方验签。
- 时间戳偏差 > 5 分钟拒收；nonce 内存 LRU 保留 10 分钟防重放。

## 五、联邦的现实约束

每个人家里都没有公网 IP。所以：

- **v0.1 单机**：只做本机实例内的注册、登录、好友（本机）、私聊（本机）、Bot + BYOK。自己和自己的 Bot 聊天完全可用。
- **v0.2 联邦**：两台机器互加好友。优先 Tailscale（免费、100 台设备、零配置打洞）；没有 Tailscale 的用 Cloudflare Worker 中继（免费 10 万请求/天）。不做自建 STUN。
- **v0.3**：局域网自动发现（同 WiFi 下直接连）。

## 六、Android 怎么处理

**手机不能当实例，只能当客户端。** 这不是偷懒，是系统限制：

1. 安卓会杀后台。应用切到后台几分钟，进程就被系统回收，服务端跟着死。想让服务器常驻，得申请前台服务 + 常驻通知 + 关电池优化，即便如此各家 ROM 还是会杀。做成「手机就是服务器」等于「对方消息永远收不全」。
2. 手机没有稳定的公网可达地址。移动网络在 NAT 后面，基站切换就换 IP，别的实例根本找不到你。
3. 电池和流量。常驻服务端 + 联邦心跳，一天下来电量和流量都吃不消。

所以分工是：

| 角色 | 平台 | 有没有服务端 |
|---|---|---|
| 完整实例 | Windows / macOS / Linux 桌面 | 有，内嵌 |
| 客户端 | Android / iOS | 没有，连实例 |

一套 React 界面三处复用：桌面用 Electron 打包（自带服务端），安卓用 Capacitor 打包（纯客户端）。

这带来一个必须提前想清楚的产品问题：**只有手机、没有电脑的人怎么办？**

答案是「加入别人的实例」：客户端启动时可以选
- 「我要一个自己的实例」→ 仅桌面版出现
- 「加入一个实例」→ 粘贴邀请码，账号建在那个实例上

这样手机用户可以加入朋友的实例，不需要自己有电脑。代价是账号归属在别人的机器上——这一点要在界面上讲明白，不能装作是独立的。

## 七、明确不做

- 端到端加密（Bot 要读消息，开了就没法做 AI 回复）
- 中心化账号、联网激活、收费
- 自动重启 / 看门狗（QQ 事故的直接教训）
- 移动端（v1.0 之后再看）
