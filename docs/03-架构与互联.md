# 架构与互联

## 单实例进程结构

```
┌─────────────────────────────────────────────┐
│  Node 进程（单进程，无守护、无自动重启）      │
│                                             │
│  Fastify HTTP :7788                         │
│   ├── /api/v1/*        本机 REST            │
│   ├── /api/v1/fed/*    跨实例联邦接口         │
│   ├── /ws              本机前端 WebSocket    │
│   └── / 静态资源        web/dist             │
│                                             │
│  SQLite  data/everpony.db                   │
│  文件     data/avatars/, data/uploads/      │
└─────────────────────────────────────────────┘
```

**只有一个进程。** 进程挂了就是挂了，没有东西会去拉它。这是刻意的：上一套系统出问题，一半原因在"自动重启"上。

## 地址模型

| 概念 | 格式 | 例子 |
|---|---|---|
| 实例指纹 | 16 位小写十六进制 | `a3f9c2d14e7b0086` |
| 号码 | 6–9 位数字 | `123456` |
| 全限定地址 fqid | `指纹.号码` | `a3f9c2d14e7b0086.123456` |
| 实例地址 | `host:port` | `100.88.3.7:7788` |

界面上一律只显示号码，鼠标悬停或点开资料才显示完整 fqid。这样看起来跟普通号码一样，但底层不会串号。

## 实例握手（TOFU）

```
A ──GET /api/v1/fed/info──▶ B
   ◀── { fingerprint, name, public_key, proto: 1 } ──
A 存进 known_instances，trust='tofu'
```

- 指纹必须与公钥哈希一致，不一致直接拒绝。
- 已经存过的指纹，公钥变了 → 标记 `trust='blocked'`，在界面上大红条警告"对方实例密钥已更换，可能被冒充"，需用户手动确认才恢复。

## 好友申请（跨实例）

```
A 用户 A1 申请加 B 用户 B1
A ──POST /api/v1/fed/friend-request──▶ B
     { from: "fpA.111111", to: "fpB.222222",
       from_name, message, ts, nonce, sig }
B 校验签名 → 写入 friend_requests(pending) → 通过 /ws 推给 B1
B1 同意 → B ──POST /api/v1/fed/friend-accept──▶ A
A 收到后两边各自写入 friendships 两条
```

**Bot 被添加走同一条链路，但多一步**：B 侧收到针对 Bot 的申请时，不推给 Bot，而是推给 Bot 的 `owner_id` 对应的人。主人同意后，才写 `bot_access`，并往 `mail_queue` 塞一封通知邮件。

## 消息投递

本实例内：直接写 `messages`，通过 `/ws` 推给在线的会话成员。

跨实例：

```
A 发消息给 B 的 B1
A 写本地 messages（状态 pending）
A 写 outbox（to_instance = fpB）
A ──POST /api/v1/fed/message──▶ B
     { conversation_id, sender_fqid, body, ts, nonce, sig }
B 验签 → 查 friendships 确认是好友 → 写 messages → 推给 B1 → 返回 ok
A 收到 ok → 标记 delivered_at，删除 outbox 行
```

### 签名与防重放

- 签名内容：`sender_fqid + conversation_id + body + ts + nonce` 的 UTF-8 拼接
- 算法：Ed25519，实例私钥签名
- `ts` 与本地时间偏差超过 5 分钟直接拒
- `nonce` 存内存 LRU（10 分钟窗口），重复直接拒
- 每实例每分钟最多 120 条跨实例消息，超了返回 429

## 三种互联拓扑

### 拓扑 A：局域网（v0.1）

同一路由器下，直接填对方 `192.168.x.x:7788`。零配置、零成本、零外部依赖。
**限制**：不在同一网络就连不上。

### 拓扑 B：Tailscale（v0.2，推荐）

双方各装 Tailscale，各得到一个 `100.x.x.x` 地址，填进"添加实例"里即可。
免费版 100 台设备，流量点对点直连，不经第三方服务器中转。
**这是"免费 + 长期可用 + 不需要公网 IP"的最优解。**

### 拓扑 C：Cloudflare 中继（v0.3，可选）

给没有公网 IP、也不想装 Tailscale 的人。用一个 Cloudflare Worker 做 WebSocket 转发，免费额度 10 万请求/天。
**只转发密文**，中继看不到内容（消息体用双方协商的密钥加密）。

## 失败处理原则

| 情况 | 处理 |
|---|---|
| 对端不可达 | 消息进 outbox，退避重试，最长 24 小时 |
| 对端实例密钥变了 | 阻断投递 + 界面告警，等用户确认 |
| 自己进程挂了 | **不自动重启**，用户手动开 |
| 数据库损坏 | 启动时报错并提示从 `data/` 备份恢复，不静默重建 |

## 安全边界

- 只监听 `127.0.0.1` 时，外部连不上（纯本机模式）
- 要互联必须监听 `0.0.0.0`，此时必须至少开启：
  - 跨实例接口的签名校验（强制）
  - 速率限制（强制）
  - 好友关系校验（非好友发来的消息直接丢弃）
- 密码、API Key 用 AES-256-GCM 加密存库，密钥文件 `data/secret.key`，权限 600
